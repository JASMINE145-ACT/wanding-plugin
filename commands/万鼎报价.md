# /万鼎报价

用户会给你一组产品描述（keywords）+ 客户等级（A-E），目标是给每条描述匹配一个**唯一**的最佳报价项。

## 工具调用

- 调 `mcp__quotation__match_quotation_batch`，参数：
  - `keywords_list`: 用户的 keywords 列表
  - `customer_level`: 用户给定的客户等级（默认 B）
  - `max 50 items per call`（schema 已限制，超出请分批循环调用）

## 选型规则

对每个返回的 `result[i]`：

1. **读 `selection_context.wanding_business_knowledge`** —— 这是 Python 端加载的万鼎业务知识，作为选型 prompt
2. **如果 `result[i].unmatched == true`** → 标记该行为 unmatched，不要强行匹配
3. **如果 `result[i].needs_selection == true`** → 用业务知识 + `candidates` 选 1 个**最契合 keywords 的**
4. **如果业务知识应用后仍无法区分** → 用 `mcp__quotation__ask_clarification` 问一句
5. **默认不要展示 candidates 全列表**（用户没显式问就别说）

## 输出格式

按用户原始 keywords 顺序，每个一行：

```
1. [matched] code=8010071381, name=#E6 PPR Coupling / dn50 - LESSO, qty=666 PCS
2. [unmatched] keywords="very obscure spec"
3. [ambiguous] keywords="PVC pipe 50", 候选需要澄清
```

## 关键约束

- 永远不要让 LLM 自由发挥选型 —— 必须读完 business_knowledge 再选
- 永远不要主动列 candidates 给用户，除非他显式要"看候选"
- 不要在 Python/MCP 之外再起一个 LLM 选型器
